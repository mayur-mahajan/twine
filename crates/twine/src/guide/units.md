# Units and display scale

Twine lays out and draws the same UI on a 240 × 240 watch panel and on a Retina desktop
window. This guide explains the units it measures in, how a display's **scale** turns them
into pixels, and what an application does to stay sharp on hi-DPI screens.

## 1. Three units

| Unit | Written | Becomes (device pixels) | Use it for |
|------|---------|-------------------------|------------|
| logical pixels, [`Length::Px`](crate::style::Length::Px) | `8`, `8.px()` | `8 × scale` | almost everything |
| density-independent, [`Length::Dp`](crate::style::Length::Dp) | `8.dp()` | `dpx(8, dpi) × scale` | one UI on panels of different density |
| device pixels, [`Length::Dev`](crate::style::Length::Dev) | `1.dev()` | `1` | hairlines, pixel-exact art |

Bare integers are logical pixels, and so are the sizes, paddings, gaps, radii, border and
shadow widths, translations and fixed grid tracks a view sets.

```
use twine::prelude::*;

let card = column((label("Title"), label("Body")))
    .padding(12) // logical pixels
    .gap(6.dp()) // the same physical size on every panel density
    .border_width(1.dev()) // a true hairline, also on a 2× screen
    .radius(8);
# let _ = card;
```

## 2. The display scale

A display's [`DisplayScale`](crate::core::DisplayScale) (`DisplayInfo::scale`) is the number
of device pixels per logical pixel: 1× on every embedded panel (a logical pixel *is* a device
pixel), 2× on a Retina screen, often 1.25× or 1.5× on Windows and Linux desktops. It is a
fixed-point ratio (256 = 1×), so fractional scales are exact for the common factors.

```
use twine::core::{ColorFormat, DisplayScale};
use twine::hal::DisplayInfo;

// A 960 × 600 window on a Retina screen: 1920 × 1200 device pixels.
let info = DisplayInfo::new(1920, 1200, ColorFormat::Xrgb8888).with_scale(DisplayScale::X2);
assert_eq!(info.logical_size(), (960, 600));
assert_eq!(DisplayScale::pct(150).to_device(10), 15);
```

The engine converts once, when it resolves a style: a `Px` (or `Dp`) length becomes a `Dev`
length of `length × scale`. Layout, hit-testing, rendering, input and every geometry the
engine reports (`Engine::coords`, scroll offsets, pointer points) are in **device pixels**;
the view layer reports logical ones where an application sees numbers (`on_scroll`). The
`DisplayInfo::dpi` of a display is the density of its *logical* pixels, so `Dp` lengths,
theme tables and size classes are the same at every scale.

The scale is a desktop feature, `display-scale`. Without it (every firmware build) the
resolver has no scale stage, and a display that reports a scale is laid out at 1× with one
warning: embedded applications pay nothing for it.

## 3. Drawing your own widget

Sizes read from styles are device pixels already. Sizes a widget makes up itself — a stroke
width, a gap, a marker — are logical pixels: convert them with
[`DrawCx::to_device`](crate::engine::DrawCx::to_device) (or `MeasureCx::to_device`, `WidgetCx::to_device`, and
`DrawCx::scale` for the factor).

```
use twine::prelude::*;

/// A 2 px (logical) accent line at the bottom of the node, sharp at every scale.
struct Underline;
static UNDERLINE: WidgetClass = WidgetClass::new("underline");

impl Widget for Underline {
    fn class(&self) -> &'static WidgetClass {
        &UNDERLINE
    }
    fn draw(&self, cx: &mut DrawCx<'_, '_>) {
        let c = cx.coords(); // device pixels
        let h = cx.to_device(2); // 2 logical pixels
        cx.painter().fill(Rect::new(c.x0, c.y1 - h + 1, c.x1, c.y1), Color::BLACK, Opa::COVER);
    }
}
```

The `line` widget's points are logical pixels too.

## 4. Fonts

A bitmap font has one size. A font that **follows the display scale** is still a
`&'static Font`, so styles, themes and labels take it unchanged; the resolver draws the
rendering made for each node's display:

- `TtfScaledFont` (feature `ttf`): a bitmap font at 1× — the
  embedded look, pixel for pixel — and the TrueType face rasterized at `size × scale` on any
  other scale, made the first time it is drawn there. The choice for desktop applications.
- [`ScaledFont`](crate::text::ScaledFont): a bitmap font with bitmap renderings for chosen
  scales (the nearest one is drawn), generated by `include_font!(…, scales = [200])`, the
  `twine-build` font builder's `.scales(..)` or `twine font --scale 200`. No floating point
  at run time.
- `TtfFont::scalable`: a run-time TrueType font that
  follows the scale.

[`scaled_font!`](crate::text::scaled_font) declares either in one line:

```
use twine::prelude::*;

twine::text::scaled_font! {
    /// Body text: Montserrat 14 at 1×, its 28 px rendering at 2×.
    static BODY = variants(fonts::MONTSERRAT_14, [DisplayScale::X2 => fonts::MONTSERRAT_28]);
}
// With the `ttf` feature, every scale from the TrueType face, symbols from Font Awesome:
// static MONTSERRAT: &[u8] = include_bytes!("assets/Montserrat-Medium.ttf");
// static FONT_AWESOME: &[u8] = include_bytes!("assets/fa-solid-900.ttf");
// twine::text::scaled_font! {
//     static BODY = ttf(fonts::MONTSERRAT_14, MONTSERRAT, 14).fallback(FONT_AWESOME);
// }

let title = label("Now playing").font(&BODY);
# let _ = title;
assert!(core::ptr::eq(BODY.for_scale(DisplayScale::X2), &fonts::MONTSERRAT_28));
```

A widget that draws text with a font it chose itself (not one resolved from a style) needs
nothing more: `DrawCx::draw_text` draws the font's rendering for the node's display.

## 5. Images

On a scaled display an image keeps its logical size: the image widget draws a plain image
zoomed by the scale. For sharp icons, give it an [`ImageSource::Scaled`](crate::image::ImageSource::Scaled)
— the 1× image plus renderings for higher scales ([`ScaledImage`](crate::image::ScaledImage));
the widget draws the smallest rendering made for at least the display's scale.

## 6. The simulator and desktop hosts

The simulator emulates panels at 1× by default and sizes its window in logical units, so a
window has its intended size on every monitor. A desktop application asks for the monitor's
scale:

```no_run
use twine::prelude::*;
use twine_sim::{SimConfig, SimScale};

twine_sim::run(
    SimConfig::new(960, 600).title("Player").display_scale(SimScale::Auto),
    |_| label("Sharp on Retina"),
);
```

`TWINE_SIM_DISPLAY_SCALE=auto|150|200` overrides it (headless runs use a fixed scale;
`.twinescript` coordinates are logical pixels). When the window moves to a monitor with
another scale, the simulator calls
`Engine::set_display_scale(display, scale)` (the display keeps its logical size): between
frames the driver resizes
its panel (`DisplayDriver::resize`), every style of the display resolves again, and the
display is laid out and redrawn. A desktop host with its own window does the same.
